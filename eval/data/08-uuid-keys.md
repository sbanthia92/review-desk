# Design: Switch primary keys from bigint to UUIDv7

## Context

All tables use auto-incrementing `bigint` primary keys generated by the database. Each of the services generate their own IDs for idempotency tokens today, which leads to alot of duplicated code.

## Proposal

Replace every primary key with a UUIDv7. UUIDs are 128 bits long, and version 7 puts a millisecond timestamp in the leading bits, so new keys sort roughly by creation time. UUIDv7 was standardized in 2019 by RFC 9562.

Random UUIDv4 keys fragment B-tree indexes because inserts land on random pages; UUIDv7 avoids that. Switching to UUIDv7 will cut our insert latency by 70%.

Every major company uses UUIDs, so we should too. It also lets clients generate IDs before they talk to the server.

## Migration

We will add a UUID column to each table, backfill it, and swap foreign keys table by table. The rollout plan is to be decided later, once we has more data.
